# 必须二次开发模块清单

依据为实际源码、SQL 和 Phase 1 安全约束。此表是后续实施范围，不是本轮已编码功能；所有资金、会员购买资格、分销、积分抵扣均冻结。

| 优先级 | 模块与改造点 | 缺口证据 | 验收门槛 |
|---|---|---|---|
| P0 | 商家主体及自营/第三方类型、商家员工登录和权限域 | `mall/document/sql/mall.sql` 无 merchant/merchant_user 表；`mall-admin` 只有平台 `UmsAdmin` | 两商家 A/B 的员工、商品、订单、库存、售后、结算对象级隔离；平台跨商家访问需独立权限和审计 |
| P0 | 商品/SKU/购物车的商家归属 | SQL `pms_product`、`pms_sku_stock`、`oms_cart_item` 无 `merchant_id` | 后端从会话确定商家；URL/body/header 伪造 ID 不越权；列表/搜索/导出不漏数据 |
| P0 | 主订单与商家子订单、商家独立履约 | SQL 只有 `oms_order`、`oms_order_item`；`OmsPortalOrderServiceImpl.generateOrder` 一次只生成一张订单 | 跨商家购物车拆子单；各商家独立发货/售后；主单聚合状态和金额一致 |
| P0 | 订单、支付、退款、售后完整状态机 | `OmsPortalOrderServiceImpl.paySuccess` 无支付状态/渠道证据/所有者前置校验；SQL 无支付尝试与退款单账本 | 重复通知、超时、取消、部分退款、重复退款、补偿均幂等；不得由客户端标记支付成功 |
| P0 | 库存预占及防超卖 | `lockStock` 先读后写；`PortalOrderDao.xml` 支付扣减无库存条件；示例 SQL 有负 `lock_stock` | 并发预占不超卖；支付扣减、超时释放、取消和退款回补均有流水与幂等 |
| P0 | 订单对象授权缺口 | `OmsPortalOrderServiceImpl.detail` 未见会员归属校验，`cancelOrder` 未见归属校验 | 跨用户/跨商家 ID 猜测 403/404、无数据副作用并有审计 |
| P1 | 商家工作台 | 仅有 `mall-admin-web` 平台后台，无商家独立前端项目 | 与平台后台权限边界分离，页面/API 同时限制商家范围 |
| P1 | 商家结算与渠道对账 | SQL 无商家应收、平台费、渠道费、佣金、结算明细、退款调整、对账异常表 | 不可变账本、状态机、幂等、差错补偿；真实资金操作仅由核实能力的持牌渠道执行 |
| P1 | 后台会员列表/详情/统计和真实报表 | 管理后端仅有 `UmsMemberLevelController`；管理端无会员列表页面；首页 `defaultLineChartData` 是静态常量 | 各项统计有明确数据来源、时间口径与权限；无演示假数据 |
| P1 | 消息、咨询、隐私政策、系统设置、登录/操作日志、备份恢复 | 移动端 `notice.vue` 为静态示例；后台无对应完整页面/API | 逐项按 134 条矩阵验收，高风险配置和备份有审计/恢复演练 |
| 冻结 | 自选/复购专区、产品/复购双积分、合伙人/联创、3999/10000、分销分红、提现 | 通用商品/单积分表不能覆盖原图规则 | 高清原图、业务规则与合规审查确认后再设计；现阶段不启用或开发资金规则 |

## 安全设计继承

继续沿用 `../../Phase1-需求拆解与最终验收报告.md` 的 `SEC-TEN-001` 至 `SEC-TEN-010`、主/子订单状态机、库存预占、结算/对账/异常补偿规则。原 mall 中相似名称的模块不自动视为满足这些条件。
