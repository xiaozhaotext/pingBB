# 四级身份与三分红池

规则版本：`2026-10-16-v1`。基于 GitHub `ecee5d3f6dca26f669525c83b0c89f0e7ad515b2` 修改。

## 已确认的业务规则

新注册用户是游客，无邀请返利或会员权益。用户在“我的 → 购买会员”单独支付3999元并确认到账后，购买者成为会员，获得3999消费/商品积分与3999复购积分，并可提交旅游路线定制需求。普通商品（包括自选区3999元商品）不会触发会员身份升级。

只有直接邀请人的付费会员资格才产生直邀权益。邀请关系在下单时快照，邀请人是否已是付费会员在被邀请人支付时判定；游客邀请人不获返利、积分、份额或有效邀请计数，之后自己成为会员也不追溯补发。符合资格的直接邀请人获得399.90元收益和1200复购积分，有效直邀数增加1。不存在间接、多层邀请奖励。

联创独立享有联创池1份、累计领取上限1200元；与合伙人池分别核算，合计最多25200元。升级不重置历史已领取金额。份数继续随有效直邀数增加，合伙人池金额上限在9人处封顶。

每笔身份牌支付入池：合伙人池500元、联创池200元、运营池200元。前两个池在本次会员入池与邀请人晋升后，按全池有效总份数自动分配；运营池由后台指定人员和份额，预览后手动发放到会员收益账户，不直接向银行卡打款。

分母为总份数。例如甲乙各2份、另8人各1份，共12份；甲乙各得1/6，其他每人各得1/12。达到累计上限的持有人不参与本池后续分配；分位舍入、封顶截断的余款留在池中，下次分配再计算。没有符合条件的持有人时余额结转，不向不存在的受益人分配。

退款及积分/奖励冲正本轮不实现，不启用新身份牌的自动退款。出现需要退款的情况，应先隔离订单并核对已产生的权益和发放账目。

每笔被邀请购买的现金承诺为900元入池＋399.90元直接返利＝1299.90元；3999元减去这些承诺后的2699.10元尚未扣除渠道费用、税费、旅游履约和7998积分的兑付成本，不能当作净利润。

## 代码与账本

- `TriPoolRules`：身份、阶梯、池金额和不超发的分配计算。
- `TriPoolService`：幂等支付事件、自动晋升、三池注资、分配批次、个人累计、审计及权威收益账本入账。
- `TriMembershipPurchaseService`：独立会员订单固定3999元，在下单时快照直属邀请关系和规则版本；渠道验签确认到账后事务发放双积分、身份及三池权益。
- `TriPoolAdminController`：三池总览、批次明细、资金流水、运营份额、预览及发放、独立会员购买、四级身份列表。
- 后台财务中心新增合伙人池、联创池、运营池三个入口；分红明细显示用户编号、用户名、发放时身份、时间、金额、个人份数、全池总份数、累计上限、此前已领和批次。
- 消费者端“我的”、推广中心和分红页显示四级身份；原合伙人/联创直接付费页面在新规则开启后改为晋升规则说明。旅游路线需求写入现有在线咨询工作流，由后台回复。
- 新代码仍使用 `ums_earnings`、`ums_earnings_ledger` 作为可提现收益来源，没有新增另一套可提现钱包。

同一购买者只能有一个未取消的身份牌订单。商品订单、支付确认、身份、双积分、直邀奖励、池注资及分配共用事务，任一关键入账失败全部回滚。各池按固定顺序加锁；发放采用当前锁定读取，避免外层订单事务的旧快照导致封顶超发。个人累计使用独立汇总行并与分红明细同事务更新。

运营发放使用请求幂等键，并重新校验预览时余额、参与人、份数、身份和累计金额的摘要；即使总份数没变，参与人替换也会使预览失效。后台操作还有服务器端平台管理员鉴权；消费者只能读取本人分红记录。会员在“我的”入口独立购买，固定3999元，合伙人及联创通过有效直邀晋升。普通商品订单不会发放身份；微信与支付宝支付必须通过已有验签链路确认，禁止客户端自行宣告付款成功。

## 上线前的迁移核对

新版本开关为 `mall.membership-v2.enabled`，默认 `false`。旧表、旧余额、旧会员身份和旧流水均未自动改写。`50_three_dividend_pools.sql` 是增量结构及菜单/资源授权，不开启真实支付或真实分红。

1. 备份真实数据库，先在独立测试库执行迁移并核对 MySQL 约束、权限和菜单。H2 测试不能替代真实 MySQL 验收。
2. 核对旧 `membership_purchase_order`、旧身份和已领金额，形成逐会员迁移清单。不能把旧“PARTNER=1/COFOUNDER=2”直接当作新四级编号，也不能仅凭普通订单价格3999认定已购买身份牌。
3. 明确旧单池余额迁入三个池的分配和每位老会员已领金额对应关系。不得自动清零旧累计或重复赠送积分与返利。
4. 处理完旧版本待付会员订单，核对所有新开关；在后台和门户同时启用新规则。未核实迁移前保持开关关闭，避免老会员被误显示为游客。回退开关前同样应处理完新规则待付订单，不能让它们被旧支付逻辑履约。
5. 核对“我的 → 购买会员”独立购买入口与3999元固定价格。正式库支付通道、模拟支付和分红相关旧开关不因本迁移自动改变。
6. 先在沙箱验证：游客注册不发权益；独立会员支付；重复通知；直邀1/2/3/4/5/6/7/8/9人；跨身份累计不重置；联创两池独立封顶；运营预览变更检测和重复请求；权限隔离；成员与三个池的账目守恒。
7. 发布两个后端和两个前端。清理管理员菜单资源缓存时仅清理授权缓存，不清空订单、购物车或全部Redis。

## 验证范围

本次本地测试使用H2内存库或模拟对象，不连接真实会员数据库，不提交真实支付、提现或分红。测试涵盖阶梯、份额分母、资金守恒、独立封顶、重复及并发通知、积分/收益失败事务回滚、支付快照和本金凭据、权限与运营发放预览。

最终构建与测试结果记录在交付目录的验收文件中；未在服务器执行的迁移、浏览器真实支付和历史数据迁移不能表述为已验收。
