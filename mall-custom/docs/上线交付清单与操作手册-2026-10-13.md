# 上线交付清单与操作手册（2026-10-13）

本文面向"明天交付/上线"。包含：交付范围、必须由业务方提供的凭证、服务器执行步骤、
逐条验收清单，以及**尚未完成、不得谎称已完成**的部分。

## 一、本次交付范围（代码已完成并通过测试）

| 模块 | 能力 | 位置 |
|---|---|---|
| 商品总控 | 商品创建/编辑/查询、批量审核、上架/下架、推荐、新品、删除 | `PmsProductController` /product/** |
| 经营总控 | 商品总数、在售/已下架、库存预警SKU、订单/待发货、会员、今日/累计已支付、退款、净收入、7日趋势 | `DashboardController` /dashboard/overview + 后台经营概览页 |
| 下单 | 真实预占库存、`Idempotency-Key` 幂等、取消释放 | `/order/generateOrder` |
| 支付-支付宝 | 电脑/手机网站支付 + 异步回调验签 + 金额核对 + 幂等 + 迟到支付补偿 | `/alipay/pay`、`/alipay/webPay`、`/alipay/notify` |
| 支付-微信 | H5/JSAPI 下单 + 结果通知验签 + 金额核对 + 幂等 + 迟到支付补偿 | `/wechatPay/h5`、`/wechatPay/jsapi`、`/wechatPay/notify` |
| 发货 | 状态校验、物流公司/单号必填、同批去重、条件更新、操作历史 | `/order/update/delivery` |
| 物流轨迹 | 快递100 实时查询 + 承运商名称映射 + 接入状态如实返回 | `/order/logistics` + 后台订单跟踪 |
| 售后/退款 | 退货三态状态机、库存归还、渠道退款（支付宝）幂等落库 | `/returnApply/update/status` + `oms_refund_record` |
| 关闭订单 | 仅待付款/待发货可关闭，条件更新校验 | `/order/update/close` |

测试证据：`mall-admin` 44 个测试（4 个为需隔离 MySQL 的既有环境用例）、
`mall-portal` 新增微信相关 12 个测试，均通过；两个前端 `vue-tsc` 无错误。

## 二、上线前业务方必须提供的凭证（缺失则该渠道保持关闭）

| 渠道 | 环境变量 | 说明 |
|---|---|---|
| 支付宝（收款+退款） | `MALL_ALIPAY_APP_ID`、`MALL_ALIPAY_APP_PRIVATE_KEY`、`MALL_ALIPAY_PUBLIC_KEY`、`MALL_ALIPAY_SELLER_ID`、`MALL_ALIPAY_NOTIFY_URL`、`MALL_ALIPAY_RETURN_URL`、`MALL_ALIPAY_GATEWAY_URL` | 需备案域名可公网回调 |
| 支付宝开关 | `MALL_PAYMENT_ALIPAY_ENABLED=true`；退款开关 `MALL_PAYMENT_REFUND_ENABLED=true` | 默认关闭 |
| 微信支付 | `MALL_WECHAT_APP_ID`、`MALL_WECHAT_MERCHANT_ID`、`MALL_WECHAT_MERCHANT_SERIAL`、`MALL_WECHAT_PRIVATE_KEY_PATH`、`MALL_WECHAT_API_V3_KEY`、`MALL_WECHAT_NOTIFY_URL`、`MALL_WECHAT_RETURN_URL` | 商户私钥为服务器上的 pem 文件路径 |
| 微信开关 | `MALL_PAYMENT_WECHAT_ENABLED=true` | 默认关闭 |
| 物流轨迹 | `MALL_LOGISTICS_ENABLED=true`、`MALL_LOGISTICS_CUSTOMER`、`MALL_LOGISTICS_KEY` | 快递100 账号 |
| 短信验证码 | `MALL_SMS_ENABLED=true`、`MALL_SMS_SIGN_NAME`、`MALL_SMS_TEMPLATE_CODE`、`MALL_SMS_ACCESS_KEY_ID`、`MALL_SMS_ACCESS_KEY_SECRET`（阿里云）或 `MALL_SMS_PROVIDER=HTTP` + `MALL_SMS_GENERIC_URL/PARAMS/SUCCESS_KEYWORD` | 模板变量必须名为 `code`；生产 `MALL_SMS_DEV_RETURN_CODE` 必须为 false |
| 应用端支付按钮 | 构建期 `VITE_USE_ALIPAY` / `VITE_USE_WECHAT_PAY` / `VITE_API_BASE_URL` | uni-app 构建变量 |
| 短信渠道 | 已实现（阿里云短信 / 通用 HTTP 短信） | 未配置凭证时验证码仅在接口返回（仅测试），后台"发送记录"如实记录 SKIPPED/FAILED |

> Spring Boot 支持用环境变量覆盖配置：即使 yml 里写的是 `false`，
> 设置 `MALL_PAYMENT_WECHAT_ENABLED=true` 也会生效。

5. 重启后端，确认启动日志无 `Failed to load ApplicationContext`。

## 四、上线验收清单（逐条真实操作，不要跳过）

- [ ] 后台登录 → 商品总控：新增商品 → 上架 → 应用端可搜索到并可下单。
- [ ] 应用端下单：生成订单 → 库存被预占（`pms_sku_stock.lock_stock` 增加）。
- [ ] 支付宝支付：支付成功 → 订单状态变为待发货 → `oms_payment_confirmation` 有记录。
- [ ] 微信支付：H5 下单跳转收银台 → 支付成功 → 同上。
- [ ] 重复回调不重复入账（幂等）；金额不一致会被拒绝并进入人工补偿。
- [ ] 后台发货：填物流公司+单号 → 状态变为已发货 → 订单跟踪可查到轨迹（已配置物流时）。
- [ ] 应用端确认收货 → 订单已完成。
- [ ] 退货：发起 → 后台确认 → 完成 → 库存归还 + `oms_refund_record` 记录退款结果。
- [ ] 经营总览：净收入 = 已支付金额 − 已成功退款金额。
- [ ] 关闭订单：仅待付款/待发货可关闭，其他状态返回 409。
