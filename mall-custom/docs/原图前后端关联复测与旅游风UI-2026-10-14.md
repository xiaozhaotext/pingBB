# 原图前后端关联复测与旅游风商品页交付

日期：2026-10-14

## 结论

平台后台与消费者商城是一套 mall 工程的不同客户端。mall-admin 和 mall-portal 分别承担管理员与消费者 API，不同登录令牌属于正常权限边界，不能直接混用。

服务器 /etc/mall-demo/admin.env 和 portal.env 中的数据源数据库均为 mall_demo；仅输出库名核对，没有输出密码。真实API核对了同一商品、会员、两类积分与专区关系。

**同一套数据已确认；完整交易、多商家与资金业务尚未全部验收。当前不适合直接正式运营。**

## 已发现问题

1. 库存检查FAIL：SKU98/102/103/106的lock_stock分别为-24/-8/-8/-8。未直接改数据库，需结合订单预占/释放记录追溯。此事实不是并发安全已通过的证明。
2. IP限制配置读取失败时安全过滤器继续放行，回归测试FAIL。
3. 审计写入失败时系统设置仍报告成功，回归测试FAIL。
4. 图片列表极大页码计算溢出，触发IndexOutOfBoundsException，回归测试FAIL。

安全探针只在本地Mock环境复现，不是在公网故意停数据库/审计服务。

## 原图缺失及未验收范围

- 原图134条保留，最新csv具有134个唯一编号；旧表84 PASS、48 PARTIAL、2 BLOCKED只代表历史记录，不能直接沿用为当前全功能验收。
- docs/原图134条本轮复验范围-2026-10-14.csv按本轮证据保守标注107 PARTIAL、27 BLOCKED；该数字表示验收范围，**不等于107条完全缺失或27条没有代码**。本轮未对每条执行所有验收步骤，因此没有批量生成PASS。
- 商品评论暂无公开接口，显示空状态；商品视频与公开评价闭环仍未验证。
- 商家仅发现pms_merchant基础表，商家员工、完整主/子订单、独立售后、结算与A/B隔离闭环不能标为PASS。
- 购物车、订单读取通过；完整模拟下单、支付、发货、取消、退款及库存竞争未在本轮部署环境全链路执行。
- 3999/10000资格、30%积分+70%现金、分享奖励、每日分红与提现等仍需要原规则确认和合规/渠道核实，保持关闭。
- 数据库还原、短信实际发送、微信配置、全权限边界和系统级功能未逐项复验。
