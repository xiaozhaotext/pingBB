# 二创分阶段实施计划

基线：`macrozheng/mall` Spring Boot 为唯一商城业务后端；管理端与移动端分别以官方 Vue 源码改造。`../ecommerce` 只用于核对 Phase 1 文档、需求追踪矩阵及既有安全约束，不再并行开发 FastAPI 商品/订单业务。每阶段单独开发、真实测试、单独验收；本轮仅审计，未启动以下改造。

## 阶段 0：接管完整性与安全基线

1. 网络恢复后在 `mall/` 补齐官方 Git 对象，核对 `origin/master` 固定 SHA、`git fsck`、`git status`；归档仅作已固定 SHA 的审计工作树，不能替代最终 Git 完整性验收。
2. 建立仅用于测试的 Java 17/Maven/MySQL 8/Redis 环境，核实 RabbitMQ、MongoDB、Elasticsearch 对最小启动的实际要求；不得自动安装系统服务。
3. 外置仓库已有 password/secret 配置，隔离演示账号和数据；封锁可由客户端直接触发的 `POST /order/paySuccess` 和真实支付入口，然后做本地编译、空测试库导入、登录/商品/订单 API 冒烟。
4. 复核原图高清源文件与 134 个现有编号；确认 Phase 1 报告“约 124”计数差异、模糊文字和节点层级。未确认规则保持冻结。

**验收门槛**：三个仓库来源/历史可验证，后端真实编译与本地 API 响应有证据，数据库只在专用测试库初始化，支付入口不会产生真实交易，移动端独立类型检查问题已定位。

## 阶段 1：商家身份、归属与后端授权

1. 在现有 MyBatis 模型和数据库上增量设计 `merchants`（`PLATFORM_SELF`/`THIRD_PARTY`）、`merchant_users`、商家角色与作用域；平台管理员仍使用原 RBAC，但跨商家访问必须有明确授权与审计。
2. 为商品、SKU、购物车项、订单、售后等逐步加入 `merchant_id` 归属与迁移；定义自营存量数据归属的可回滚迁移。
3. 在服务和 DAO 层强制商家上下文，不信任客户端 merchant_id；修复现有 `detail`、取消、发货等对象级授权缺口。新增独立商家工作台登录边界。
4. 按 `SEC-TEN-001` 至 `SEC-TEN-010` 建真实 A/B 越权集成测试；未实现的资源保持 `NOT IMPLEMENTED`，不能虚报通过。

**验收门槛**：商家 A/B 对商品、员工和已实现资源的读写隔离可实测；伪造 URL/body/header、批量 ID、搜索和导出均不泄露，拒绝操作无副作用且留审计。

## 阶段 2：商品、库存、购物车与多商家订单

1. 保留原 Pms/Oms 代码，补商家商品归属和独立库存；用数据库条件更新/版本控制实现库存预占、支付确认扣减、超时释放、取消和退款回补，记录库存流水。
2. 在原移动购物车上增量做商家分组；一次结算生成主订单与各商家子订单，商品、运费、优惠与应付金额按已确认规则计算，不提前写入原图未确认积分抵扣。
3. 改造主/子订单状态机，商家独立发货、收货与售后；处理超时、重复动作和异常补偿。

**验收门槛**：并发防超卖；跨商家购物车真实拆单；订单金额守恒；商家 A/B 订单、库存与售后隔离；状态转换有前置条件、幂等与审计。

## 阶段 3：支付/退款抽象、商家账务与对账

1. 先定义渠道无关的支付/退款尝试、状态机、回调验签、查单、去重和 outbox 补偿；无真实渠道资质及能力核实前只用隔离沙箱或测试替身。
2. 增量设计商家应收、平台服务费、渠道手续费、商家待/已结算、退款调整、佣金账本与渠道对账记录；所有金额使用精确数值及不可变明细，支付渠道实际分账能力独立核实。
3. 商家工作台补订单、售后、结算只读/审核能力，并完善异常工单、对账差异处理及审计。

**验收门槛**：重复通知/退款、部分退款、冲正、重试和差错对账实测；数据库账面余额不被描述为真实资金到账。真实支付和资金分账的启用另行审批。

## 阶段 4：原图专项会员/积分/分销与剩余运营功能

1. 先核对合伙人、联创、3999/10000、产品积分、复购积分、30%/70%、奖励 10%/200 元、分红上限等原图原文，完成购买资格/多层级计酬合规审查和财务口径确认。
2. **仅在明确批准后**改造原单一 `ums_member_level`/`integration` 模型，不沿用黄金/白金/钻石等级替代原图；分账、佣金提现和特殊积分抵扣保持独立开关及账本。
3. 按 134 行差异矩阵补全消息、咨询、后台会员管理、真实报表、系统设置和备份恢复等缺口，每个编号保留独立验收用例。

**验收门槛**：每个规则有原图依据、业务签认和合规结论；资金/积分/推广流水可追溯，退款冲正闭环；所有矩阵项逐项标记真实 PASS/FAIL/待确认。

## 阶段 5：全系统联调与部署准备

在专用测试环境做真实 MySQL/Redis/消息队列/搜索集成、负载与并发测试、A/B 安全回归、支付沙箱对账、数据库备份恢复演练、前后端构建与 API 兼容验收。部署生产环境需另行批准，本计划不授权部署。

## 冻结规则

现阶段不开发或启用真实支付、资金分账、会员购买资格、多级分销、分红、提现及特殊积分抵扣。任何阶段不得以“原 mall 已有相似功能”为由合并或删去原图独立需求。阶段顺序可在用户确认后细化，但不得跳过前置安全和运行验收。
