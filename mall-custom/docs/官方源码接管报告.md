## 2. 实际依赖与边界

- 根 `mall/pom.xml` 定义 `mall-common`、`mall-mbg`、`mall-security`、`mall-demo`、`mall-admin`、`mall-search`、`mall-portal`，并声明 MyBatis `3.5.19`、MySQL Connector/J `9.3.0`、Java `17`。`mall-portal/pom.xml` 依赖 Redis、MongoDB、RabbitMQ、支付宝 SDK；`mall-search/pom.xml` 依赖 Elasticsearch。`mall-admin/pom.xml` 包含 OSS/MinIO 客户端。能否在禁用外围服务的最小配置下启动，尚未实测。
- 管理端 `package.json` 声明 Vue `^3.5.25`、Element Plus `^2.12.0`、Vite `^7.2.4`、TypeScript `~5.9.0`；实际构建输出 Vite `7.3.0`。移动端声明 Vue `^3.5.20`、uni-app `3.0.0-5000720260410001`、Vite `^5.2.8`、TypeScript `^5.1.6`。锁文件决定本机安装的精确依赖图。
- `mall-admin-web/package.json` 的 Node 要求为 `^20.19.0 || >=22.12.0`；本机 Node 24.19.0 符合声明。两个前端均有 `package-lock.json`，使用锁文件安装，不重建锁。
- 仓库现有 `application-dev.yml`、`application-prod.yml` 含 password/secret 类配置键。未在报告输出具体值；运行前必须做凭据来源和有效性核查，并用环境变量或外置配置隔离。移动端 `.env.production` 指向官方演示 API，不可作为本项目后端验收地址。
- 原后端的支付宝相关源码存在于 `mall-portal/.../AlipayController.java`、`AlipayServiceImpl.java`。本轮没有调用、配置或启用真实资金渠道。

## 3. 源码审计结论

| 领域 | 实际证据 | 接管判断 |
|---|---|---|
| 分类、品牌、SPU/SKU、属性、图片、上下架 | `mall-admin/.../PmsProductController.java`、`PmsProductCategoryController.java`、`PmsBrandController.java`、`PmsSkuStockController.java`，`mall-admin-web/src/views/pms`，SQL `pms_product`/`pms_sku_stock` | 单商户基础模块可复用 |
| 搜索/筛选 | `mall-portal/.../PmsPortalProductController.java`、`mall-search`、`mall-app-web/src/pages/product/search.vue` | 基础搜索存在；自选/复购商品类型和多商家过滤缺失 |
| 购物车与订单 | `OmsCartItemServiceImpl.java`、`OmsPortalOrderServiceImpl.java`、`mall-app-web/src/pages/cart/cart.vue`/`order/createOrder.vue` | 单商户路径存在；无商家拆单 |
| 订单取消/发货/收货/售后 | `OmsPortalOrderServiceImpl.java` 的取消/确认收货、`mall-admin/.../OmsOrderServiceImpl.java` 发货、`OmsOrderReturnApplyServiceImpl.java` 退货状态更新 | 现有状态 0–5 为单订单状态；退货申请只更新状态/金额，未见渠道退款流水与幂等执行；不符合 Phase 1 主/子订单、退款单和状态机 |
| 会员与积分 | `UmsMemberController.java`、`ums_member`、`ums_member_level`、移动端个人页 | 普通会员、单一 `integration` 存在；原图合伙人/联创和产品/复购双积分不存在。SQL 种子为黄金/白金/钻石/普通会员，不能替换原图等级 |
| 收藏、足迹、地址 | 移动端 `productCollection.vue`、`readHistory.vue`、`address.vue` 及对应 portal Controller | 通用功能可复用 |
| 平台后台 | `mall-admin-web/src/views/pms`、`oms`、`sms`、`ums` 与后端对应 Controller | 商品、订单、促销、角色资源可复用；完整后台会员管理、财务账本、系统运维菜单未见闭环 |
| 报表 | `mall-admin-web/src/views/home/index.vue` 内 `defaultLineChartData` 常量和 `setTimeout` | 图表当前为静态演示，不能算真实统计 |
| 多商家 | 全 SQL 共 76 个 `CREATE TABLE`；检索 `merchant_id`、`seller_id`、`shop_id`、商家主体/结算表无匹配；`pms_product`、`oms_cart_item`、`oms_order` 无归属列 | **不支持**第三方商家主体、员工独立登录、商家库存、购物车分组、主/子订单、商家售后、结算和 A/B 隔离 |

### 多商家逐项核查

| 用户要求的能力 | 源码/表证据 | 判定 |
|---|---|---|
| 平台自营商家、第三方商家主体 | SQL 无商家主体表或商家类型；`pms_product` 无归属列 | 不支持 |
| 商家员工独立登录 | `ums_admin`/`UmsAdminController` 为平台管理员模型，无商家员工关系 | 不支持 |
| 商家商品归属、商家独立库存 | `pms_product`、`pms_sku_stock` 无 `merchant_id` | 不支持 |
| 多商家购物车 | `oms_cart_item` 无商家归属；`mall-app-web/src/pages/cart/cart.vue` 为通用购物车 | 通用购物车支持，多商家分组不支持 |
| 主订单与商家子订单 | `OmsPortalOrderServiceImpl.generateOrder` 只生成一个 `OmsOrder`，所有 item 共用该 ID | 不支持 |
| 商家独立发货 | `mall-admin/.../OmsOrderServiceImpl.delivery` 按普通订单 ID 批量发货 | 不支持 |
| 商家售后 | `OmsOrderReturnApplyServiceImpl` 处理退货申请状态，无商家范围 | 不支持 |
| 商家结算 | SQL 无商家结算/对账/服务费/渠道费/佣金账本表，相关服务检索无结果 | 不支持 |
| 商家 A/B 数据隔离 | 商品、订单、售后、员工缺商家归属字段和后端作用域 | 不支持 |

## 4. 需优先封锁的现有风险

1. `mall-portal/.../OmsPortalOrderController.java` 暴露 `POST /order/paySuccess`；`OmsPortalOrderServiceImpl.paySuccess` 仅凭 `orderId` 把状态改为待发货并扣库存，没有先校验支付渠道、订单当前状态和请求人。`application.yml` 的白名单未包含 `/order/**`，但**登录用户也不应能自行确认支付**。后续接管时必须禁用该入口并以可信回调+查单+幂等取代；本轮未调用或修改。
2. 同服务的 `detail(orderId)` 按 ID 查询并返回商品/收货资料，未见会员归属校验；`cancelOrder(orderId)` 也未见会员归属校验。应在真实环境和安全测试中验证并修复，不能把现有认证当作对象级授权。
   `OmsPortalOrderReturnApplyServiceImpl.create` 直接复制申请参数入库，未见申请人对订单的归属核验；退货申请也需对象级授权。
3. `lockStock` 先读取 `pms_sku_stock` 再写回锁定量，`PortalOrderDao.xml` 的支付扣减 SQL 未见 `stock >= quantity`/版本条件；源码无法证明防超卖。SQL 示例中还存在负 `lock_stock` 值，示例数据不可直接作为正确库存基线。
4. `mall-admin/.../OmsOrderServiceImpl.delivery` 批量发货未见商家归属和子订单校验；现有管理员 RBAC 不能代替商家行级隔离。
5. Phase 1 要求的支付/退款状态机、部分退款、重复通知/退款幂等、对账和结算账本均需增量设计与测试。支付宝示例代码存在不等于这些条件已满足。

## 5. 接管约束

继续使用 Spring Boot 主工程；`ecommerce` 只作设计与安全对照，不并行维护 FastAPI 商城业务。原图 3999/10000、积分抵扣、推广奖励、分红和提现保持冻结。先完成商家归属与对象授权、订单/库存安全改造方案及真实环境基线，后续每阶段由用户确认后实施。
