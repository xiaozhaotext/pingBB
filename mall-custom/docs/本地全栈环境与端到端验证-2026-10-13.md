# 本地全栈环境与端到端验证（2026-10-13）

为了在**不碰线上服务器**的前提下验证修复，本机（Windows）从零搭起了一套完整运行环境，走通了“后台改数据 → 应用端立即变化”的全链路。

## 一、环境位置与组成（全部装在 D 盘，分目录存放）

根目录：`D:\mall-local-stack\`

| 子目录 | 组件 | 端口 |
|---|---|---|
| `mysql/` + `mysql-data/` | MySQL 8.0.42（zip 版，非服务、免安装） | 3306 |
| `redis/` + `redis-data/` | Redis 5.0.14.1（Windows 版） | 6379 |
| `mongodb/` + `mongodb-data/` | MongoDB 8.0.4 | 27017 |
| `erlang/` | Erlang/OTP 26.2.5.6（RabbitMQ 依赖） | — |
| `rabbitmq/` + `rabbitmq-data/` | RabbitMQ 3.13.7（vhost `/mall`，账号 mall/mall） | 5672 |
| `logs/` | 各组件与两个 Java 应用的日志 | — |
| `bin/` | `start-all.ps1`（起四个服务）、`start-apps.cmd`（起两个应用）、`stop-all.ps1` | — |

启动：`bin\start-all.ps1` → `bin\start-apps.cmd`；停止：`bin\stop-all.ps1`。详见 `D:\mall-local-stack\README.md`。

## 二、数据库

`mall` 库共 128 张表，由仓库脚本构建：`mall.sql`（76 张基础表 + 演示数据）→ `custom-v10/01..28*.sql`（按文件名顺序的增量迁移）→ `custom-product-zones*.sql`（自选/复购区演示数据）。

应用启动时用命令行参数把数据源指向 `127.0.0.1:3306/mall`，**没有修改仓库里的 `application-dev.yml`**。

- 管理后台接口 `http://127.0.0.1:8080`，账号 `admin / admin123`
- 应用端接口 `http://127.0.0.1:8085`，会员 `test / 123456`

## 三、端到端验证结果（全部实测通过）

先把本机数据造成与线上一致的状态：商品 27 商品价 `998`、其 SKU 价 `2699`、SKU 98 `stock=86 / lock_stock=-24`。

| 项 | 复现（修改前） | 修复后实测 |
|---|---|---|
| 商品价同步 | 列表页读 `pms_product.price=998`，详情页/购物车读 `pms_sku_stock.price=2699`，两处不一致 | 后台把商品价改为 `1200` 后，**列表、详情、4 条 SKU、购物车全部为 1200** |
| 库存不足 | 旧 SQL 条件（`stock>=0 AND lock_stock>=0`）对 SKU 98 匹配 **0 行** → 报“库存不足” | 新 SQL 条件匹配 **1 行**；实际下单成功（订单号 202610130100000001，应付 1920） |
| 分类“显示”开关 | 后台 `showStatus=0` 后应用端 `categoryTreeList` 仍返回该分类 | 关闭后应用端分类树**立即不再返回**，还原后恢复 |
| 品牌“显示”开关 | 后台 `showStatus=0` 后 `/brand/detail/{id}` 仍返回品牌 | 关闭后详情**返回空**，`recommendList` 同步剔除，还原后恢复 |
| 数据修复脚本 | `lock_stock<0` 1 条、SKU 最低价≠商品价 1 个商品 | 执行 `deploy/demo/fix-sku-stock-price-2026-10-13.sql` 后均已归一，前后报告附在输出中 |

数据修复脚本对本机 `mall` 库执行成功（脚本无 `USE`/建库语句，schema 相对，可直接用于服务器 `mall_demo`）。

## 四、结论

- 代码修复在**真实运行的应用**上验证有效，5 个缺陷中的 4 个（价格同步、库存不足、分类显隐、品牌显隐）已在本机端到端跑通；第 5 个（品牌区顶部按钮文字刷白）为纯样式修复，已随前端构建产物生效。
- 本机环境与演示服务器相互独立。线上要生效仍需：部署 `codex/live-data-repair` 分支 + 执行数据修复 SQL（见 `docs/上线阻塞点与一键部署包-2026-10-13.md`）。
