## 2. 对照原图发现的关键差异

1. **首页与导航（REQ-FE-HOME-004～006）**：原图要求自选区推荐、复购区推荐及“首页、自选区、复购区、我的”四个底部入口。当前移动端是“首页、分类、购物车、我的”。购物车在原图中是独立分支，不是该导航条目的第五项。已修正 Phase 1 和差异矩阵中的旧误读。不能把普通分类页面重命名后冒充自选/复购专区。
2. **自选与复购商品（REQ-FE-PICK-*、REQ-FE-REBUY-*）**：当前通用商品分类、搜索、详情、加购代码可作为基础，但没有专区商品属性、独立列表/筛选、双积分账本及对应订单类型。原图的 30% 复购积分 + 70% 现金需确认资格、计算、退款与会计口径后才可实现和启用。
3. **购物车及订单（REQ-FE-CART-*、REQ-ADM-ORDER-*）**：单商户商品和购物车页面存在，商家名称、跨商家购物车、主单/子单、商家独立发货与售后不存在可验收实现。Phase 3A 库存并发和部分订单授权有服务层测试，但完整 HTTP 下单、消息队列超时、支付通知和退款闭环未通过。
4. **会员、分销与个人中心（REQ-FE-DIST-*、REQ-FE-ME-*、REQ-ADM-MEMBER-*）**：原图的普通会员/合伙人/联创、3999/10000、产品积分/复购积分、邀请、10%/200 元、每日分红和提现不能用 mall 原有会员等级或单一积分替代。当前缺少原图所需的数据与流程；比例和门槛保持原文，模糊节点待确认，合规审查前不启用。
5. **后台财务及设置（REQ-ADM-FIN-*、REQ-ADM-SET-*）**：缺乏原图所列财务明细、佣金审核、真实用户统计、公司信息、上传/水印、访问/IP/短信/微信设置、图片管理及备份恢复等闭环。后台首页目前直接写入“今日订单 200”“销售额 ￥5000”和固定趋势数据，必须尽快接真实聚合 API 或明确显示“暂无数据”，不能用于客户演示。
6. **消息与咨询（REQ-FE-HOME-003、REQ-FE-PICK-015、REQ-FE-ME-013）**：消息页是静态示例，当前没有真实消息、已读/未读或咨询工单。页面存在不代表这些需求完成。
7. **平台自营 + 第三方商家（用户追加的专项约束）**：原图并未完整画出商家工作台，但用户已明确这一项目模式。`docs/Phase3A多商家数据库迁移设计.md` 和 SQL 仅是评审草案，未执行；商家身份、商品/SKU 归属、员工 RBAC、A/B 隔离、子单和结算全部不能标记为已实现。

## 3. 优化建议与顺序

### P0：先修演示真实性与交易安全

- 后台首页移除固定统计、固定趋势与固定待办数量，接真实聚合数据；API 未完成前展示明确空状态。
- 清理官方示例广告、历史促销词、商品和演示账号；仅用业主授权的测试素材展示。当前本地数据库含官方示例数据，不适合直接给客户看。
- 补齐本地 RabbitMQ/Redis Server 所需验收，再实测完整下单、超时释放、重复请求、模拟支付通知、迟到支付与退款补偿。Phase 3A 的 12 个 JUnit 测试不覆盖完整交易闭环。
- 多商家能力正式开放前，先实施可回滚迁移、服务端商家作用域、A/B 越权测试。没有这层隔离时，商家工作台只能展示明确标注的非操作原型。

### P1：按原图补核心业务

- 在商品模型中定义自选/复购分类归属，建立独立首页推荐、列表、详情和可追踪订单类型；不启用未经确认的积分支付。
- 建主订单/商家子订单与独立库存、发货、售后；实现跨商家购物车分组与金额守恒。
- 实现会员管理后台、个人资料、收货地址、订单、收藏、足迹的真实 API 对接；把消息与在线咨询从静态页面改为真实记录。
- 电脑 Web 与移动端使用同一后端，但逐页完善桌面商品详情、购物车、结算和个人中心，不仅是首页加宽。

### P2：规则确认后再开发/启用

- 核对合伙人/联创资格、3999/10000 金额、两类积分、30%/70%、10%/200 元、分红上限、提现扣费等原图规则；对模糊文字提供高清源文件或逐条签认。
- 核实支付服务商是否具备多商家分账/退款能力，完成合规与会计口径审查，再设计渠道集成。数据库余额不能代表真实到账。
- 按后台设置 21 条和财务 8 条逐项补齐，并建立每条需求的页面/API/表/验收用例记录。

## 4. 当前可验证范围与限制

- 本地 `mall-admin`、`mall-portal`、后台 Web 与商城 H5 已启动；商城首页和推荐商品 API 曾返回 HTTP 200。HTTP 200 只证明服务响应，不证明订单可完成。
- 管理后台 TypeScript/构建和商城 H5 构建已有通过记录；宽屏全流程浏览器验收未完成。
- Phase 3A 报告记录 Java/Maven 编译和 12 个 JUnit 测试通过，也明确完整下单、签名回调、退款和商家隔离尚未通过。当前使用 Garnet 兼容服务，不等同于原生 Redis Server 验收。
- 因上述差距，当前系统属于可继续开发和局部演示的测试基线，**不能按原图 134 条要求认定 V1.0 已完成，也不具备正式运营条件**。
