## 3. 静态配置与运行风险

- `mall/mall-admin/src/main/resources/application.yml` 与 `mall/mall-portal/src/main/resources/application.yml` 默认 `dev` profile。管理前端 `.env.development` 指向 `http://localhost:8080`，移动端指向 `http://localhost:8085`；后端配置端口与该意图一致。未连接真实本机后端。
- 移动端 `.env.development` 的 `VITE_USE_ALIPAY=true`，portal 源码有支付宝 Controller。因本项目冻结真实支付，**在隔离测试环境完成支付入口封锁前不得按原样对外启动可访问系统**。本轮未修改配置或发起任何支付。
- 后端 `application-dev.yml`、`application-prod.yml` 含密码/密钥配置项；未输出值。运行前需外置真实凭据并核查是否为样例或已泄露凭据。
- `mall/document/sql/mall.sql` 有 76 个 `CREATE TABLE`，含样例数据和 `DROP TABLE IF EXISTS`；不得直接导入现有业务数据库，只可在新建专用测试库验证。样例 `pms_sku_stock.lock_stock` 可见负值，库存验收必须先隔离样例数据。
- 管理首页 `mall-admin-web/src/views/home/index.vue` 的图表由静态 `defaultLineChartData` 提供，构建成功不代表报表真实。

## 4. 本地非 Docker 运行步骤（待环境批准后执行）

1. 在专用测试环境准备 JDK 17、Maven、MySQL 8、Redis；根据 `mall-portal/pom.xml` 与 `mall-search/pom.xml` 决定 RabbitMQ、MongoDB、Elasticsearch 的实际启动范围。安装服务、改系统配置或下载大体积中间件前须另行获批准，本轮未执行。
2. 新建专用 MySQL 测试库与最小权限账号，**先审阅** `mall/document/sql/mall.sql` 的 `DROP TABLE` 与示例账号/数据，再只向空测试库导入。不要对 `ecommerce` 或其他数据库执行。
3. 将数据库、Redis、消息队列及外部服务连接参数通过本地隔离配置注入，确认支付接口和移动端支付宝入口在测试环境不可执行真实交易。检查仓库已有凭据并轮换需要轮换的值。
4. 在 `mall/` 执行 `mvn -pl mall-admin,mall-portal,mall-search -am -DskipTests package`，记录真实编译输出；再按 `mall-admin`、`mall-portal`、`mall-search` 的 profile 分别本地启动。随后验证登录、商品、订单 API 与依赖健康。
5. 前端在各自目录运行 `pnpm dlx npm@11.6.2 ci --no-audit --no-fund`；管理端 `pnpm dlx npm@11.6.2 run build`，移动端 `pnpm dlx npm@11.6.2 run build:h5`。需补查移动端 `tsc` 与当前 TypeScript/vue-tsc 组合的兼容性，不能靠跳过检查宣称通过。

## 5. 验收结论与待批准事项

官方源码的**前端构建基线已验证**。Spring Boot 编译、MySQL 初始化、后台登录、商品/订单 API 基线和多商家安全均**未通过完整运行验收**。下一轮需用户批准准备本机/独立测试环境的 JDK、Maven 与所需数据库/中间件服务；如仅允许只读审计，可继续源码设计，但不得宣称项目可运行。
