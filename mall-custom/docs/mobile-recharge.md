# 手机端充值接入

基于 origin/main 4160d88。入口：我的 → 账户充值；当前支付拉起针对手机 H5（微信 H5 支付、支付宝手机网站支付）。原生 App / 小程序支付需各自产品权限及 SDK 拉起适配，当前页面会提示使用手机浏览器，不会假装付款成功。

充值本金独立存入 `ums_recharge_account`，不增加可提现收益、佣金、分红或积分。本次实现充值和到账记录，未改变购物订单的余额抵扣规则。`ums_recharge_order` 同时是充值入账凭证，保存渠道交易号、到账时间和到账后余额；客户端金额、余额、订单金额都使用固定两位小数字符串。

## 开通步骤

1. 在测试库执行 `mall/document/sql/custom-v10/43_mobile_recharge.sql`，上线前备份并对生产库执行同一迁移。
2. 合并 `deploy/demo/recharge-payment.example.yml` 到服务端实际加载的部署配置，配置商户号、应用号、签名密钥文件、微信 API v3 密钥。仅填写环境变量而未加载该示例配置不会自动启用；也可直接绑定 `mall.recharge.payment.*`。
3. 微信通知 URL 为 `https://商城域名/member/recharge/notify/wechat`；支付宝通知 URL 为 `https://商城域名/member/recharge/notify/alipay`，需按实际 API 代理前缀调整。支付宝 return-url 指回商城 `/#/pages/member/recharge`（按路由模式调整）。回调必须公网 HTTPS 可达，反向代理必须原样传递微信正文与签名头。
4. 配置微信 H5 支付域名，支付宝手机网站支付权限；入口是浏览器支付，微信内置浏览器需切到外部浏览器完成 H5 支付。
5. 开启总开关 `mall.recharge.payment.enabled` 及已获批的渠道 enabled；未开通渠道保持关闭。充值配置与会员购买支付配置互相独立，回调地址不可混用。
6. 用真实渠道测试小额付款、重复通知、失败重试、通知中断及恢复后查单补偿，核对渠道账单和充值凭证，再开放用户充值。当前没有真实商户凭证，未完成渠道实付验收。

## 金额与一致性

- 后端严格校验人民币金额，范围 0.01～50000.00 元，最多两位小数；数据库只保存整数分，不使用浮点运算。
- 创建订单不入账；支付跳转、客户端成功提示都不入账。服务端验签并检查商户、应用、币种、交易状态后，再核对订单金额和渠道。
- 实付少一分或多一分均不自动入账，拒绝通知并保留待核查订单；不静默按错误金额记账。此类异常需人工与渠道账单核对、处理退款或差额，不能宣称自动避免渠道自身的异常扣款。
- 同一用户同一请求编号只能创建一笔订单，修改金额或渠道会拒绝。网络结果不明时页面保留请求编号供原请求重试；继续支付复用原商户订单号。
- 到账时在同一数据库事务内锁定订单、锁定本金账户、更新余额、记录交易号及到账凭证。重复同一通知直接返回成功；跨订单复用交易号触发唯一约束，整个事务回滚。多笔订单并发到账不会丢失余额更新。
- 每分钟主动查询待到账订单（每轮100笔，按最后查单时间轮转），查询结果复用同一入账事务，弥补通知丢失；保持未支付或异常订单待核查，不以时间到期直接丢弃可能已支付订单。高流量应监控补偿积压并调整批量与频率；原始渠道日账单仍须对账。

## 接口

登录态接口均从当前认证用户取得 memberId，不信任客户端 memberId：

- GET `/member/recharge/account`：本金余额，两位小数字符串。
- POST `/member/recharge/orders`：`{"amount":"100.10","channel":"WECHAT","requestId":"至少16位字母数字或横线"}`。
- POST `/member/recharge/orders/{orderNo}/pay`：拉起同一订单支付。
- GET `/member/recharge/orders/{orderNo}`：仅查询本人订单。
- GET `/member/recharge/orders`：本人最近50笔记录。

## 验证

`RechargeServiceTest` 使用隔离的 H2 MySQL 模式数据库验证金额精度、少付、多付、重复通知、交易号复用时事务回滚、并发到账、请求重试和权限归属；`MembershipPaymentGatewayTest` 验证未配置渠道拒绝支付。H2 不代替真实 MySQL 与支付平台联调验收。

最新 main 原有 `OmsPortalOrderServiceImpl` 引用了不存在的 `portal.domain.OmsOrderItem`，本分支将其修正为实际的 `model.OmsOrderItem` 以通过后端编译。
