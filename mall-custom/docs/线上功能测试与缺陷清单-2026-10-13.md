## 二、重要声明：本轮测试误删了两行演示数据

后台有两个**删除接口被声明为 GET**（上游 mall 原样如此，不是本项目二次开发引入的）：

- `PmsBrandController#delete` → `@RequestMapping(value="/delete/{id}", method=RequestMethod.GET)`
- `PmsProductAttributeCategoryController#delete` → 同样为 `RequestMethod.GET`

端到端 GET 全量探测因此真实触发了这两个删除接口（均返回 `code:200`），删除了：

| 表 | 被删行 |
|---|---|
| `pms_brand` | id=1 `万和` |
| `pms_product_attribute_category` | id=1 `服装-T恤`, 2, 5 |

已核对：`PmsProductAttributeCategoryServiceImpl#delete` 只执行 `deleteByPrimaryKey`，**没有级联删除**，
因此该分类下的 7 个 `pms_product_attribute` 行仍然完好。影响面就是上表两行。

恢复脚本已生成：`mall-custom/deploy/demo/restore-demo-rows-2026-10-13.sql`（`INSERT IGNORE`，可重复执行，不会覆盖已有行）。

## 三、缺陷清单

### BUG-1（严重）服务端错误被统一伪装成 `code:401`，导致 App 直接强制退出登录

- 现象：请求失败时，响应体不是真实错误，而是 `{"code":401,"message":"暂未登录或token已经过期","data":"Full authentication is required to access this resource"}`。
- 根因：后端异常会转发到 `/error`，而 `/error` **不在** `secure.ignored.urls` 白名单里，
  错误分发再次经过 Spring Security → 未认证 → `RestAuthenticationEntryPoint` 覆盖了真实错误体。
  所以 `HTTP 400/415/500` 都会带上 `code:401` 的壳。
- 放大：`mall-app-web/src/utils/http.ts:114` 是 `if (res.statusCode === 401 || body?.code === 401) { handleExpiredSession(...) }`，
  于是**任何服务端错误都会清 token 并跳登录页**。
- 影响：用户点「我的收藏 / 我的足迹 / 品牌关注」等入口，等待约 30 秒后被强制登出（详见 BUG-2）。
  管理端同样会弹「你已被登出，可以取消继续留在该页面，或者重新登录」。
- 修复建议：两个服务的 `application.yml` 白名单加 `/error`；前端只在 HTTP 状态码为 401 时登出。

### BUG-2（严重）MongoDB 未部署/未配置，收藏、足迹、品牌关注三个功能全挂

- 现象（实测耗时与响应）：

| 接口 | 耗时 | HTTP | 响应体 code |
|---|---|---|---|
| `/portal/member/productCollection/list` | 30.2s | 500 | 401 |
| `/portal/member/readHistory/list` | 30.1s | 500 | 401 |
| `/portal/member/attention/list` | 30.2s | 500 | 401 |

- 30.x 秒正好是 MongoDB 默认 `serverSelectionTimeout`，是连不上 Mongo 的典型特征。
- 根因：`deploy/demo/configure-services.sh` 生成的 `portal.env` **没有** `SPRING_DATA_MONGODB_HOST`，
  部署脚本也没有安装 MongoDB，而 portal 的 `application-prod.yml` 里 `spring.data.mongodb.host: mongo` 是 docker-compose 主机名，解析不了。
- 影响：移动端「我的收藏」「我的足迹」「品牌关注」三个页面及其“清空/删除”操作完全不可用，
  并且因为 BUG-1 还会把用户登出。对应页面确实调用这些接口（`pages/user/productCollection.vue`、`readHistory.vue`、`brandAttention.vue`）。
- 修复建议：服务器安装并启动 MongoDB 后配置连接；或把这三个功能改用 MySQL 落地（仓库里已有会员相关表，可评估）。

### BUG-3（严重）删除类操作以 GET 暴露，可被链接、预取或爬虫触发

- 证据：`GET /admin-api/brand/delete/1` 与 `GET /admin-api/productAttribute/category/delete/1` 都返回 `code:200` 并真实删除了数据（见第二节）。
- 同类问题：`GET /portal/cart/update/quantity?id=&quantity=` 会修改购物车数量（`OmsCartItemController.java:58`）。
- 影响：不需要任何交互即可造成数据删除/修改；没有二次确认，也没有独立的权限资源约束。
- 修复建议：改为 `POST/DELETE`，前端同步修改，并给删除接口加独立资源授权。

### BUG-4（高）参数错误也伪装成 401，误导排查

- 证据：`POST /admin-api/admin/login` 用 `application/x-www-form-urlencoded` 提交 → `HTTP 415`，响应体却是 `code:401`；
  `GET /admin-api/memberLevel/list` 缺 `defaultStatus` → `HTTP 400`，响应体同样是 `code:401`。
- 补齐参数后均返回 `code:200`（`/productAttribute/list/1?type=0`、`/memberLevel/list?defaultStatus=0` 实测正常），
  说明接口本身没问题，是错误通道被 BUG-1 的机制污染了。
- 修复建议：同 BUG-1。

### BUG-5（高）图片地址仍为 `http://`，HTTPS 页面触发浏览器混合内容拦截

- 实测计数：
  - 首页 `/portal/home/content`：`http://` **47 个**，`https://` **0 个**（banner、品牌、分类图标全部中招）。
  - 商品详情 `/portal/product/detail/26`：富文本 `detailHtml` 内的描述图 6 个 `http://`，品牌 `logo`/`bigPic` 也是 `http://`。
- 影响：HTTPS 页面会拦截这些图片，首页 banner、分类图标、商品详情描述图、品牌 logo 都不显示。
- 说明：商品主图/相册用的是相对路径 `/oss/mall/images/...`，实测 `200 image/jpeg`，是正常的，不需要改。
- 修复建议：把数据库里这些 `http://macro-oss...` 地址批量替换为 https（或改自托管图床），并清洗 `detailHtml` 富文本。

### BUG-6（中）`/portal/order/list` 的 `status` 是必填，缺省即 400

- 证据：`OmsPortalOrderController.java:80` `@RequestParam Integer status` 没有 `defaultValue`；不带 `status` 请求返回 HTTP 400。
- 现状：App 订单页始终会带上 `status`（`pages/order/order.vue` 用 `navItem.state`，默认 -1），所以目前不影响界面，
  但接口不健壮，且这个 400 又会触发 BUG-1 的表现。
- 修复建议：`status` 改为可选，缺省表示全部。

### BUG-7（中）后台 `flashSession/selectList` 缺参数时抛 NPE 返回 500

- 证据：`GET /admin-api/flashSession/selectList`（不带 `flashPromotionId`）→ HTTP 500；带上参数 → `code:200`。
- 原因：`SmsFlashPromotionSessionController#selectList(Long flashPromotionId)` 未做空值处理，直接透传到 SQL。
- 修复建议：`flashPromotionId` 加必填校验或空值短路，返回 400 而不是 500。

### BUG-8（低）小程序专区非法 zone 抛异常返回 500

- 证据：`GET /portal/product/zone/1` → HTTP 500。`ProductZoneController.java:30` 对非法 zone 直接
  `throw new IllegalArgumentException("未知商品专区")`。
- 影响：非法专区码会 500，并叠加 BUG-1 把用户登出。
- 修复建议：改为 404/400，或返回空列表。

### BUG-9（低）后台 OSS 上传凭证接口未授权

- 证据：`GET /admin-api/aliyun/oss/policy` → `code:403 未授权`（角色 5 没有该资源）。
- 影响：若后台改用阿里云 OSS 上传会失败。当前上传组件走的是 MinIO 上传地址，所以暂时不影响演示。
- 修复建议：确认上传方案后补资源授权，或移除该入口。

## 四、已确认正常

- 后台 77 个真实 GET 接口中 69 个返回 `code:200`（另有 1 条为解析脚本产生的伪路径，已剔除）。
- 应用端 57 个 GET 中跳过 4 个（3 个支付类 + 1 个会改购物车数量的 `GET /cart/update/quantity`），实测 53 个，38 个返回 `code:200`。
- 应用端首页、购物车、优惠券、地址、发票地址、通知公告、积分台账、收益台账、邀请、咨询、提现列表、商品搜索/分类树等均正常。
- 应用端 `/member/points/account`、`/member/dividend/mySnapshot`、`/member/attention/detail`、`/member/productCollection/detail`、
  `/brand/productList`、`/sso/getAuthCode` 等接口在补齐必填参数后均返回 200，是探测方法缺参，不是接口缺陷。
- `/portal/member/dividend/detail`、`/portal/member/dividend/snapshot` 返回 403，是 `p0-public-blocks.nginx.conf` 有意关闭的资金类入口，符合预期。

## 五、非缺陷的观察（供参考）

- JWT 的 `exp` 用的是毫秒时间戳（`JwtTokenUtil` 生成与校验两侧一致，功能正常），
  但不符合 JWT 规范（规范要求秒）。如果有网关或第三方库参与校验会解析失败，建议后续统一成秒。
- 后台 `admin` 的 `roles` 显示为「超级管理员」，但 `/aliyun/oss/policy` 返回 403，说明实际生效的是角色 5 的资源清单而不是“超管特权”，命名与行为不一致。

## 六、建议修复顺序

1. BUG-1 + BUG-4（错误通道）：白名单放行 `/error`，前端只在 HTTP 401 时登出。改完 BUG-2/6/7/8 的表现都会立刻变得可诊断。
2. BUG-2（MongoDB）：安装配置 Mongo，或把收藏/足迹/品牌关注改为 MySQL 落地。
3. BUG-3（GET 删除）：改 POST/DELETE，并执行恢复脚本补回被删的两行演示数据。
4. BUG-5（http 图片）：批量替换为 https。
5. BUG-6/7/8/9：接口健壮性与授权收尾。

> 说明：本轮新写的「平台设置 / 图片管理 / 隐私政策 / 水印」等代码**尚未发布到该服务器**，因此线上不存在这些接口
> （`/portal/home/siteInfo`、`/p0/system-settings/*` 实测 404），不在本清单范围内。

## 九、发布后的复核方法

- 用 GET 调 `GET /admin-api/brand/delete/1` 应返回 **405**（改为 POST 生效），POST 调用仍可正常删除。
- 故意触发参数错误，例如 `GET /admin-api/memberLevel/list`（不带 `defaultStatus`），应返回**真实 400 报文**，
  不再是 `code:401 "暂未登录或token已经过期"`。
- 应用端点「我的收藏 / 我的足迹 / 品牌关注」：装好 Mongo 后应返回 200；若仍未装，应看到错误提示而**不再被登出**。
- 首页在 HTTPS 下应能正常显示 banner 与品牌 logo（控制台不再有混合内容告警）。
