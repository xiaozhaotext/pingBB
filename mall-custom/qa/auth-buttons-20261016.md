# 沙盒注册与登录按钮修复验收

## 定位与修复

- 手机视口375×667下，注册页使用固定 `height:100vh` 和 `overflow:hidden`，注册按钮超出容器后被裁切；验证码或错误提示出现后表单还会继续增高。改为内容撑高、可滚动，并禁止装饰元素参与点击命中。
- 登录样式原为全局样式，已限定到本页，避免 `.container`、输入框和按钮样式影响其他页面。
- 登录请求等待时没有文字反馈，部分异常仅打印控制台。新增登录中/跳转中状态和持续可见错误提示；验证码与注册同样增加加载状态、失败反馈和重复点击保护。
- 登录→注册→重定向登录可能留下两个登录页，原 `navigateBack()` 会回到旧登录页。现在跳过登录/注册来源页并进入首页；从业务页要求登录时仍可返回原业务页，导航失败回首页。
- 登录成功但会员资料加载失败时，清理本次未完成会话；不保留半登录状态。验证码倒计时在页面卸载时释放。

验证码按钮在本地旧构建可以触发请求，因此未将所有现象归因为点击事件未绑定；这次同时修复了可复现的裁切、反馈及导航问题。远程旧构建或网络问题仍需部署后核对。

## 浏览器实际操作

本地独立H2数据库，使用生产注册Controller/Service、MyBatis会员Mapper、BCrypt密码校验、JWT鉴权、会员订单、履约、积分与三池事务。验证码缓存使用内存适配器；短信与支付为模拟，未调用真实短信或付款渠道。

1. 手机375×667：填写新账号，点击获取验证码，按钮显示获取中，随后页面显示6位验证码和60秒倒计时。
2. 输入返回的验证码，实际点击注册，成功进入登录页。
3. 错误密码登录显示“用户名或密码错误”，按钮恢复可操作；修改为正确密码后登录成功并进入首页。
4. 进入会员权益页，点击3999元沙盒支付。购买完成后重新读取，身份为会员，分红资格与已领取金额来自实际履约事务。
5. 设置页点击退出并确认，回到登录页；再次打开会员页被要求重新登录，确认会话已清理。
6. 另一个新账号从“登录→马上注册”进入，完成注册再登录，成功进入首页，未退回旧登录页。
7. 恢复桌面视口，检查登录按钮中心命中按钮自身，装饰层 `pointer-events:none`。

证据：`auth-code-mobile.png`、`auth-membership-mobile.png`、`auth-logout-mobile.png`、`auth-browser-evidence.json`。测试启动器为 `AuthFlowBrowserHarness`（仅测试源码，默认绑定本机并使用独立内存库）。
