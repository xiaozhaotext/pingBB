# 会员购买与三池演示修复

## 修复内容

- 四身份权益页根据后台支付能力显示沙箱支付或已开通的真实渠道。沙箱构建与后台环境必须一致；正式页面不确认模拟支付。
- 支付桩仍走会员下单、已验证支付履约、积分、身份及三池事务；没有直接修改前端余额或伪造分红流水。
- 同账号清缓存或换设备后，同渠道的未支付订单可恢复，保留原金额、规则及订单号；不同渠道冲突明确返回56005，重复购买返回56004。
- 直接打开设置页也能退出到登录页。后台退出不再因服务端会话失效而卡住，清空旧角色与菜单。
- 移除四个页面标题中的“模拟”，会员身份列显示中文，避免重复显示身份代码/名称；数据加载失败有提示。
- 沙箱后台使用独立缓存键、独立后端8087，连接与沙箱应用相同的mall_demo_sandbox数据库。保留醒目的不扣款标识。
- 沙箱启用与正式站一致的四身份规则；正式模拟支付仍关闭。修正Vite通过mode加载沙箱环境时的资源路径。

## 本地验证

- 44项身份、三池、购买、回调与权限后端测试通过，另2项支付能力测试通过。
- 11项应用端回归测试通过，包含重复点击、环境不匹配、下单失败重试和生产环境禁止确认模拟支付。
- 隔离H2/MySQL兼容环境，真实BCrypt/JWT登录、MyBatis积分及事务：18项HTTP验收通过。
- 浏览器实际点击沙箱购买：local_ref_11由游客变会员，商品/复购积分各3999，出现分红账户入账；设置页退出后进入登录页。
- 本地账号为独立测试数据，缓存/角色有测试替身；不代表完整生产基础设施或真实商户支付验收。

## 部署与验证

1. 构建Java时使用`-Ddocker.skip=true`，不需要Docker。
2. 应用分别构建正式和沙箱；沙箱使用`.env.sandbox`及`build:h5:sandbox`。
3. 后台分别设置`VITE_BASE_SERVER_URL=/admin-api`及`/sandbox/admin-api`，沙箱设置`VITE_SANDBOX_MODE=true`，再运行`npm run build`。
4. 按deploy-membership-sandbox.py的清单打包并生成SHA256 manifest，在服务器先备份两库、服务文件和旧程序，再切换版本。
5. 独立沙箱入口：`/sandbox/`；对应后台：`/sandbox/admin/`。正式后台不能显示沙箱库产生的流水。
6. 保留旧示例账号和历史数据；不清空或重算历史余额。用新测试账号验收购买、推荐晋升、三池注资与重复回调幂等。

真实微信/支付宝收款、银行打款，以及已支付会员退款逆向冲账不在本次沙箱验收范围内。
