# 沙盒下级身份、订单展示与池账核验

基线：main `0b66b33`。本轮保留三区支付规则及现有账号密码、个人账户、订单状态和订单金额，只发布沙盒程序与静态页面。

## 核对与修改

1. 下级列表原接口仅返回推荐关系，页面固定显示“会员ID”。现接口按开启的新旧会员体系返回 `membershipTier`；页面使用“用户ID”，显示实际身份，分别统计邀请总人数、付费身份人数、游客人数。游客保留在推荐关系列表中，不加入有效付费直邀。
2. 5笔所谓“未支付但待发货”订单实际均为 `pay_type=3` 的已确认沙盒模拟支付。原后台支付方式缺少该类型并回退“未支付”，已改为明确显示“沙盒模拟支付”；未知类型不再冒充未支付。订单关闭也不再直接显示为已退款。销量金额统一展示余额与外部支付合计，保留既有现金统计字段供原调用方使用。
3. 13.70元差额由历史清理归档流水 `ARCHIVE:90` 的6.85元支出被记成正数造成。此次排查时服务器记录已修正为-6.85元；未再次增减个人账户或池资金。日账新增全量流水累计与当前池余额的差额、收支方向异常数及对账状态，异常在后台明确提示。昨日的本机清理脚本已同步修正，并增加带符号流水合计及收支方向校验；没有重新运行清理。
4. 历史订单160、161与保留订单147、148编号重复，诱因是清理Redis后订单自增序号重置。排查时服务器已分别修复160、161编号，并存在订单号唯一索引。新代码使用持久化订单ID和含N的独立编号空间，先插入获取ID、再在同一事务内保存订单号，避免缓存丢失及旧数字编号碰撞。迁移58提供可重复执行的唯一索引保护，发现历史重复时拒绝建索引，不自动删单。
5. 订单148：商品总额3499，活动优惠200，复购积分989，外部支付2310，余额支付0。金额数值正确，原列表“订单金额”和详情“应付款”比较了不同字段。现列表与详情分别显示商品总额、资金应付（余额加外部支付）、余额支付及外部支付，不以总额替代零应付，不重复计算运费和折扣。

## 未更改的三区规则

- 自选区：余额全额支付或外部渠道支付，不用积分。选择余额且不足时不可结算，可充值或改选外部支付。
- 复购区：当前复购积分比例30%，积分按整数向下取整；开启积分时，先抵扣复购积分，再使用可用余额，差额进入外部支付。也允许关闭积分抵扣。积分不足不会自动从商品积分扣除。
- 消费区：100%商品积分支付，当前1积分抵1元；积分不足不允许下单，不转成余额或外部支付。
- 当前没有把订单外部支付差额自动先充值进余额的统一流程。用户本轮选择只核实规则，不改变支付方式。
